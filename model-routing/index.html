MODEL ROUTING / 04

役割ごとに、モデルを使い分ける。

Codex / Claude Codeを置き換えるのではなく、判断と編集に集中させ、反復処理を役割別に分けるためのモデル運用です。

CODEx / CLAUDE CODE + LOCAL SYSTEM

単体エージェントの強みを、運用で薄めない。

CODEX / CLAUDE CODE単体

探索・設計・例外対応に集中できる

依頼の背景を読み、難しい判断や制作上の例外を解く力がある。反面、繰り返しの生成・承認状態・同期手順は会話ごとに再確認が必要になりやすい。

LOCAL AI CONTENT OPERATIONS

繰り返しの実行をローカルへ寄せる

候補生成、検査、広告状態、同期、公開確認を工程化する。エージェントは「何を作るか」「何を採るか」により多くの時間を使える。

ROLE FIT

モデルは役割で選び、出荷は共通の品質ゲートを通す。

PLAN

構成・レビュー候補

thinking系を、本文を直接書かせるよりも判断・比較の工程へ使う。

WRITE

日本語本文の下書き

公開済み検証ログの比較を踏まえ、Qwen3.5 9Bを標準候補として扱う。

CODE

Blade / PHPなどのファイル生成

qwen2.5-coder系を候補にし、書込み先の制限とtest/buildを必須にする。

EXPERIMENT

検証ログ

単一の最強モデルを決めず、複数モデルを比較対象として評価を残す。

失敗は、次のモデル選定に使う。

検査する

事実・数値・日本語・Markdown・途中切れ・PR表記を確認する。

同じ出力に固執しない

不良が出たら、再プロンプトだけでなくモデル変更を検討する。

判断を残す

どのモデルを採ったか、なぜ止めたかを次回の工程へ引き継ぐ。
